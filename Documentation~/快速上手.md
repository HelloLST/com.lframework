# LFramework Core 快速上手

> **目标**：在一个新 Unity 工程里，30 分钟内点亮 **日志 / 资源 / UI** 三条链路。
> 本文件只讲“从零到跑起来”。模块 API 细节、事件系统、对象池、本地化等见同目录 `使用说明.md`。

---

## 0. 前置条件

| 项 | 要求 |
|---|---|
| Unity | 2022.3 LTS |
| UniTask | **必须**。框架 Runtime 程序集直接依赖它，不装则整个包编译不过 |
| 脚本后端 | Mono / IL2CPP 皆可（包内 `link.xml` 已保留 LFramework 程序集，防清单反射被裁剪） |

## 1. 安装

### 1.1 先装 UniTask（二选一）

```jsonc
// Packages/manifest.json —— 方式 A：git URL
"com.cysharp.unitask": "https://github.com/Cysharp/UniTask.git?path=src/UniTask/Assets/Plugins/UniTask"
```

```jsonc
// 方式 B：OpenUPM scoped registry
"scopedRegistries": [
  { "name": "OpenUPM", "url": "https://package.openupm.com",
    "scopes": ["com.cysharp.unitask"] }
],
"dependencies": { "com.cysharp.unitask": "2.5.10" }
```

### 1.2 再装 LFramework Core

```jsonc
// Packages/manifest.json
"com.lframework.core": "https://github.com/HelloLST/com.lframework.git#v0.9.0"
```

本地联调（改包源码即时生效）：

```jsonc
"com.lframework.core": "file:../../com.lframework"
```

> ⚠️ `file:` 的相对路径以 **`Packages/` 目录**为基准，**不是工程根目录**。写错会在 Console 报 `package.json cannot be found`。
> ⚠️ 本地 `file:` 包**不会**进 `Library/PackageCache`，而是直连源目录。

### 1.3 确认装好了

Project 窗口出现 `Packages/com.lframework.core`，Console 无编译错误。

## 2. 让框架跑起来

**框架不会自启动。** 需要一份模块清单 + 一个 `ModuleManager`。

### 2.1 创建模块清单资产

菜单 `LFramework/Create Module Manifest Asset`，或代码兜底：

```csharp
var manifest = ModuleManifest.CreateDefault();   // 7 个默认模块，依赖已排好
```

`ModuleManifest.CreateDefault()` 的内容：

| 模块 | typeName | dependsOn |
|---|---|---|
| TimerMgr | `LFramework.TimerMgr` | — |
| LogManager | `LFramework.LogManager` | — |
| AudioManager | `LFramework.AudioManager` | — |
| MonoManager | `LFramework.MonoManager` | — |
| ResourcesManager | `LFramework.ResourcesManager` | — |
| ObjectPoolsManager | `LFramework.ObjectPoolsManager` | `LFramework.MonoManager` |
| UIManager | `LFramework.UI.UIManager` | `LFramework.ResourcesManager` |

清单是 ScriptableObject，Inspector 里可增删/拖拽排序，**不用改代码**。初始化顺序由 `dependsOn` 拓扑排序决定，无依赖的模块保持清单里的顺序（顺序是稳定的，不是字典枚举顺序）。

### 2.2 挂 ModuleManager 并初始化

`ModuleManager` 是 **MonoBehaviour**，挂到场景里一个常驻 GameObject 上：

```csharp
using LFramework;
using UnityEngine;

public class GameLaunch : MonoBehaviour
{
    [SerializeField] private ModuleManifest _manifest;

    private async void Awake()
    {
        var moduleManager = GetComponent<ModuleManager>();
        await moduleManager.InitializeAsync(_manifest);
        // 到这里，清单里的模块都已完成 InitializeAsync
        LogManager.Info("框架启动完成");
    }
}
```

要点：

- 清单里**没有** `ModuleManager` 自己 —— 它是驱动者，不是模块。
- 初始化完成前不要调 `UIManager.Open<T>()` / `ResourcesManager.Load<T>()`。
- 业务模块也走清单：实现 `IModule`、把 `typeName` 写进清单、需要逐帧就**额外实现 `ITickable`**（不实现就不会被派发，不再被迫写空 `Tick`），跨模块用 `ModuleManager.GetModule<T>()` 获取并把对方 `typeName` 写进自己的 `dependsOn`。

## 3. 三条链路

### 3.1 日志（先点亮它 —— 后面两条出问题都靠它查）

```csharp
LogManager.Debug("调试信息");
LogManager.Info("启动完成");
LogManager.Warning("配置缺失，用默认值");
LogManager.Error("加载失败", ex: exception);
```

| 特性 | 说明 |
|---|---|
| 启动期缓冲 | 在 `await InitializeAsync` **之前**打的日志不会丢：先进静态缓冲（容量 256），`LogManager` 就绪后回放 |
| 配置资产 | `Assets/Resources/LogSettings.asset`（也可走编辑器面板改）。**资产缺失时用默认值**，不会空引用 |
| 可配项 | 最低级别 / 控制台 / 文件 / 编辑器内 / 脱敏 / 异常捕获 / 保留天数 / 堆栈 / 刷盘模式 / 远程上传 |
| 刷盘时机 | 由 `ITickable.Tick()` 驱动，经 MonoManager → ModuleManager 单一出口（业务侧不要自己起协程刷盘） |

### 3.2 资源

```csharp
// 同步加载（仅 Resources 后端支持）
var sprite = ResourcesManager.Instance.Load<Sprite>("Icons/coin");

// 异步加载（推荐；Addressables 后端只能走这个）
var clip = await ResourcesManager.Instance.LoadAsync<AudioClip>("Audio/bgm");

// 归还隐式持有 —— 与 Load / LoadAsync 配对
ResourcesManager.Instance.Release("Icons/coin");

// 需要“使用期间别被缓存淘汰”：拿句柄
using (var handle = ResourcesManager.Instance.Pin<Sprite>("Icons/coin"))
{
    var s = handle.Get<Sprite>();
    // ... 使用
}   // Dispose 即归还那一次显式引用
```

**引用计数契约（容易搞错，重点看）**：

| 动作 | 语义 |
|---|---|
| `Load` / `LoadAsync` | 首次加载产生一次**隐式持有**（RefCount=1）；**缓存命中不新增** |
| `Release(path)` | 归还隐式持有（与 `Load` 配对）。**未废弃**，是当前推荐用法 |
| `Pin<T>(path)` | 返回 `IResourceHandle`，在隐式持有之上再加一次**显式引用**；`Dispose()` 幂等归还 |
| `AddRef` / `ReleaseRef` | **已标 `[Obsolete]`**，请改用 `Pin<T>`。保留一个版本周期后移除 |

缓存策略：容量上限（默认 100，`SetMaxCacheCount`）+ LRU 淘汰。**被句柄钉住且不是 GameObject 的资源不会被容量淘汰**（强卸会破坏使用中的贴图/音频）；全部不可回收时允许暂时超限，但绝不会自旋。诊断用 `GetCacheInfo()` / `GetCacheCount()` / `IsCached(path)`。

### 3.3 UI

需要两份资产 + 一条路径约定。

**(a) UIRoot 预制体** —— 默认路径 `Assets/Resources/Prefabs/UI/UIRoot.prefab`，结构：

```
UIRoot
  ├─ Camera        （UI 相机）
  ├─ EventSystem
  └─ Canvas
       ├─ Normal
       ├─ TopBar
       └─ PopUp
```

三个层级节点的**名字**取自 `UIPanelLayer` 枚举（`Normal` / `TopBar` / `PopUp`，顺序须与枚举一致）。要改成别的名字，在 `Assets/Resources/` 放一份 `UISettings` 资产改 `layerNodeNames`，**不用改框架代码**。

**(b) 面板预制体** —— 路径 = `Prefabs/UI/UIPanel/{面板类型名}`。例如类名 `UIMainPanel` → `Assets/Resources/Prefabs/UI/UIPanel/UIMainPanel.prefab`。

**(c) 面板类**：

```csharp
using LFramework.UI;
using UnityEngine;
using UnityEngine.UI;

public class UIMainPanel : UIPanelBase
{
    // 命名约定自动绑定：字段名按下划线拆分，首段须命中前缀
    // 前缀集合：btn / img / obj / text / input / slider / scroll / ui
    [SerializeField] private Button btn_start;
    [SerializeField] private Text text_title;

    public override void OnUIStart()
    {
        btn_start.onClick.AddListener(OnStartClicked);
    }

    public override void OnUIDestroy()
    {
        btn_start.onClick.RemoveListener(OnStartClicked);
        base.OnUIDestroy();      // 必须调用：内部会退订数据绑定并销毁实例
    }

    private void OnStartClicked() { /* ... */ }
}
```

打开 / 关闭 / 传参：

```csharp
UIManager.Instance.Open<UIMainPanel>();                          // 同步加载（仅 Resources 后端）
var panel = await UIManager.Instance.OpenAsync<UIMainPanel>();   // 异步，推荐
UIManager.Instance.OpenAsync<UIMainPanel>(someArgs);             // 传参

UIManager.Instance.Close<UIMainPanel>();      // 默认销毁；标了 [UIKeepAlive] 的只隐藏、保留实例
UIManager.Instance.Back();                    // 关闭栈顶并回到上一个
```

**生命周期时序（关键）**：

```
OnUIAwake → OnUIStart → InitPanelData(data) → OnUIEnable → OnShowAnimation → (State = Open)
```

**数据是在 `OnUIStart` 之后才到的** —— 不要在 `OnUIStart` 里读 `InitPanelData` 的参数。要在显示时同步初值，用下面的数据绑定。

面板属性：`[UILayer(UIPanelLayer.PopUp)]` 指定层级；`[UIKeepAlive]` 关闭时只隐藏不销毁。`State` 状态机为 `Opening / Open / Closing / Destroyed`。`OnUIEnable()` / `OnUIDisable()` 内部会 `SetActive(true/false)`，**子类覆写时必须调 `base`**。

**数据绑定（`BindableProperty<T>`）**：

```csharp
// Model 侧：字段包一层
public readonly BindableProperty<int> Count = new BindableProperty<int>(0);
Count.Value = 3;                    // 值真的变化时才通知；同值赋值不触发

// 面板侧：订阅
protected override void OnUIStart()
{
    Bind(model.Count, v => text_count.text = v.ToString(), invokeImmediately: true);
}
```

- `Bind` 建立的订阅会被登记，并在面板 `OnUIDestroy()` 时**自动退订** —— 你不需要手写 `-=`。
- 保活面板隐藏时不销毁，订阅保留，重新显示时数据仍是最新的。
- 初始化后想强制刷一次 UI：`ForceNotify()`，或 `Bind(..., invokeImmediately: true)`。

## 4. 常见坑

| 现象 | 原因与解法 |
|---|---|
| `该路径下:Prefabs/UI/UIPanel/Xxx未查找到此面板` | 预制体路径或名字不符。必须是 `Resources/Prefabs/UI/UIPanel/{类型名}` |
| 界面打不开且无报错 | 忘了挂 `ModuleManager`，或没 `await InitializeAsync(_manifest)` |
| 数据已加载，界面还是旧值 | 在 `OnUIStart` 里读数据 —— 数据在 `InitPanelData` 才到。改用 `Bind(..., invokeImmediately: true)` |
| 业务脚本找不到 `LFramework` 命名空间 | `LFramework.asmdef` 是 `autoReferenced: false`，业务程序集必须**显式引用**它 |
| 业务程序集找不到 UniTask | asmdef 的 `references` **非传递性**：引用 LFramework ≠ 拿到 UniTask，必须自己写 |
| 业务脚本放 `Assets/Scripts/` 根目录编译失败 | 会落进默认 `Assembly-CSharp`，而它不自动引用 LFramework。请建自己的 asmdef |
| 第二次进 Play 状态不对 | 关闭 Domain Reload 时静态状态会跨会话残留。框架已对自身静态做重置；业务自己的静态缓存请加 `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` 清理 |

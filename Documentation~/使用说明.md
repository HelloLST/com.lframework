## 1. 项目概览

### 1.1 定位

LFramework 是面向 Unity 中小型项目（含上位机 / 训练类应用）的**轻量级运行时框架**，提供 UI、资源、对象池、音频、计时器、事件、日志、本地化、网络协议、状态机等核心能力。

### 1.2 技术栈

| 项 | 内容 |
|---|---|
| 引擎 | Unity 2022.3.62f3c1（China LTS） |
| 语言 | C# 9.0 |
| 异步 | Cysharp UniTask（git 包 `com.cysharp.unitask`） |
| JSON | Newtonsoft.Json（`com.unity.nuget.newtonsoft-json` 3.2.1）；本地化表也用它解析（`LocalizationManager` 走 `Newtonsoft.Json.Linq`） |
| UI | UGUI（`com.unity.ugui`） |
| 测试 | Unity Test Framework 1.1.33（NUnit） |

### 1.3 模块总览

```
启动引导    ModuleManager（清单驱动）
核心分层    LFramework（运行时）+ LFramework.Editor（编辑器）两个程序集
基础设施    单例、统一更新、事件中心、SO 数据层、配置、暂停、日志、架构护栏
表现层      UI 面板栈管理、资源加载（可换后端）、对象池、音频、计时器、本地化、场景加载
输入/交互   InputKeysManager（按键事件派发）、FSM 状态机
通信        UDPDevice（多线程安全）
```

## 2. 安装与配置

### 2.1 环境要求

| 项 | 要求 |
|---|---|
| Unity | 2022.3.62f3c1 或同 2022.3 LTS 系列 |
| 操作系统 | Windows（本机开发）/ Android / WebGL（目标平台） |
| 包依赖 | 需联网拉取 UniTask（git 包）；框架包本体见 §2.3 |

### 2.2 安装到工程

1. **先装 UniTask**（见 §2.3）—— `LFramework` 程序集直接依赖它，不装则整个包编译不过。
2. **在 `Packages/manifest.json` 加入框架包**：

   ```jsonc
   "com.lframework.core": "https://github.com/HelloLST/com.lframework.git#v0.9.0"
   ```

   本地联调改用 `file:` 相对路径，例如 `"com.lframework.core": "file:../../com.lframework"`。
   ⚠️ `file:` 的相对路径以 **`Packages/` 目录**为基准，**不是工程根目录**；写错会在 Console 报 `package.json cannot be found`。
3. **确认装好**：Project 窗口出现 `Packages/com.lframework.core`，Console 无编译错误。若出现 `CS0246`（类型找不到），多半是 asmdef 引用缺失，参见 §3.2 程序集分层。

## 3. 架构总览

### 3.1 设计目标

三步重架构后确立的三条硬约束：

1. **编译期分层**：框架不能引用业务类型，由 asmdef 强制，不靠人自觉。
2. **清单驱动的初始化**：模块的创建 / 顺序 / 依赖由 ScriptableObject 描述，改模块不必改代码、不必重编译。
3. **单一逐帧出口**：全工程逐帧逻辑从 `MonoManager.Update()` 流出，避免多个 `MonoBehaviour.Update()` 各自为政。

### 3.2 程序集分层（包内 2 个程序集）

框架本身是一个**独立的 UPM 包** `com.lframework.core`，包内程序集分布：

| 程序集 | asmdef 路径 | 归属 | 引用 | autoReferenced |
|---|---|---|---|---|
| **LFramework** | 包 `Runtime/LFramework.asmdef` | 包 | UniTask | **false** |
| LFramework.Editor | 包 `Editor/LFramework.Editor.asmdef` | 包 | LFramework | true（Editor-only） |

**要点**

- `LFramework` 的 `autoReferenced: false` → 业务程序集必须**显式引用**它，否则找不到 `LFramework` 命名空间。
- asmdef 的 `references` **非传递性**：业务程序集引用了 LFramework ≠ 自动拿到 UniTask，必须自己写。
- 包内用**名字**引用 UniTask（可移植）。
- **预编译 DLL 例外**：`Assets/Plugins` 下、以及来自其他包的 `.dll`，在 `overrideReferences: false` 时对所有程序集**自动可用**，无需列入 `references`。本框架包**自身不含任何 .dll**。
- **不要把业务脚本放在 `Assets/Scripts/` 根目录** —— 会归入默认 `Assembly-CSharp`，而它不自动引用 `LFramework`，必然编译失败。请建自己的 asmdef。

### 3.4 模块系统

三个文件构成：

| 文件 | 职责 |
|---|---|
| `Core/ModuleSystem/IModule.cs` | 模块生命周期接口 |
| `Core/ModuleSystem/ModuleManifest.cs` | SO 清单 + `ModuleEntry` + Kahn 拓扑排序 + `CreateDefault()` 兜底 |
| `Core/ModuleSystem/ModuleManager.cs` | 读清单 → 类型解析 → 有序创建 → 依次初始化 → 统一 Tick → 逆序 Dispose |

**生命周期**

```csharp
public interface IModule
{
    string DisplayName { get; }          // 日志/诊断用显示名
    UniTask InitializeAsync();           // 创建后按拓扑序依次 await
    // 逐帧能力已拆到 ITickable，IModule 不再含 Tick          // 由 MonoManager.updateEvent 统一驱动
    void Dispose();                      // 逆序执行（退出时跳过）
}
```

**实例创建规则（`ModuleManager.CreateInstance`）**

| 类型 | 创建方式 |
|---|---|
| `MonoBehaviour` 派生 | `gameObject.AddComponent(type)`（挂在 ModuleManager 所在物体上） |
| 纯 C# 单例（有静态 `Instance` 属性，即 `SingletonBase<T>` 模式） | 反射读 `Instance` 触发懒创建 |
| 其它 | `Activator.CreateInstance(type, nonPublic: true)` |

**销毁规则**

- `OnDestroy` 先反注册 `updateEvent`。
- 若 `Application.quitting` 已置位 → **跳过** `Dispose()`（此时交给各管理器自身的 `OnDestroy`）。
- 运行期销毁（如场景卸载）→ **逆序** `Dispose()`。

**默认清单（`CreateDefault()`）实际包含 7 个模块**

```
TimerMgr → LogManager → AudioManager → MonoManager → ResourcesManager
→ ObjectPoolsManager (dependsOn: LFramework.MonoManager)
→ UIManager          (dependsOn: LFramework.ResourcesManager)
```

> `LocalizationManager`、`LoadSceneManager`、`InputKeysManager` **不在清单内**：三者都是纯 C# 单例（首次访问 `Instance` 时自初始化）。

### 3.5 单例与访问约定

两套单例基类：

| 基类 | 适用 | 说明 |
|---|---|---|
| `UnitySingleton<T>` | 需要挂 GameObject、用协程 / Update 的管理器 | 自动查找或创建宿主物体并 `DontDestroyOnLoad` |
| `SingletonBase<T>` | 纯 C# 管理器（无需挂载） | 首次访问 `Instance` 时反射构造并调用 `Init()` |

`UnitySingleton<T>` 已做三项加固：

1. **重复实例守卫**：新增 `_isDuplicate` 旗标。派生类 `Awake()` 必须在 `base.Awake()` 之后检查，为 true 时立即 `return`，跳过自身初始化。
   ```csharp
   protected override void Awake()
   {
       base.Awake();
       if (_isDuplicate) return;   // ← 必须
       Init();
   }
   ```
2. **退出标记**：`_isQuitting` 由 `Application.quitting` 事件与 `protected virtual void OnApplicationQuit()` 两处置位；两者都不走 `OnDestroy`（避免运行期单例被销毁后其它单例的 `Instance` 返回 null 造成自锁死）。
3. **DontDestroyOnLoad 时序**：场景未加载完成时延迟到 `sceneLoaded` 回调执行，规避引擎断言。

**访问约定（重要）**

| 场景 | 正确方式 | 原因 |
|---|---|---|
| 访问 **Core 框架管理器**（TimerMgr / LogManager / AudioManager / MonoManager / ResourcesManager / ObjectPoolsManager / UIManager） | `X.Instance` | 既定约定，全工程 30+ 处合法用法 |
| 访问 **业务模块 / 跨模块依赖** | `ModuleManager.GetModule<T>()`，并在自身 `dependsOn` 中声明 | 避免初始化期对方未就绪导致空引用 |
| 工具类单例（无生命周期） | `X.Instance` | 无需进清单 |
| **只想探查、不想创建单例** | `UnitySingleton.TryGetExisting(out T)`；只读探针 `IsExisted` / `IsQuitting` | 避免“只看一眼”却顺手把单例造出来 |

> **唯一硬性规则**：在 `InitializeAsync()` 内访问另一个**业务模块**时，必须同时做到
> ① 通过 `GetModule<T>()` 获取；② 把对方的 `typeName` 写进自己的 `dependsOn`。
> 否则对方可能排在你后面还没创建 → 空引用。日常 `Tick()` 内跨模块调用无此限制。

### 3.6 统一更新系统

```
MonoManager.Update()
  └─ updateEvent (UnityAction)
       └─ ModuleManager.OnModulesTick()
            └─ 遍历 _modules → IModule.Tick(deltaTime)
```

- `ModuleManager` **自身没有 `Update()`**，注册 / 反注册时机为 `InitializeAsync` 完成后 / `OnDestroy` 开头。
- `IsInitialized` 为 false 时不派发 Tick。
- `MonoManager` 另提供 `AddFixedUpdateListener` / `AddLateUpdateListener`，以及 `StartCoroutine` / `StopCoroutine` 代理。**协程代理仅为业务兼容保留，框架内部一律用 UniTask**（见 §7 规则 3）。

> **现状说明（Phase 5 / 5.1 收编后）**：现在只有 `MonoManager` 保留 `MonoBehaviour.Update()`，作为唯一驱动入口；`TimerMgr` / `ObjectPoolsManager` / `LogManager` 的逐帧逻辑已改为实现 `ITickable` 的 `Tick(float)`，三者各自的 `Update()` 均已删除（`LogManager` 残留的那处于 2026-10-12 补删）。`IModule` 不再含 `Tick`，因此不存在“空 Tick”一说。

### 3.7 SO 数据层（`LFramework.Architecture`）

| 类型 | 用途 | 一句话理解 |
|---|---|---|
| `ScriptableVariable<T>`（Int/Float/Bool/String） | 跨系统共享变量 | 生产者只管写，消费者只管订阅，双方互不认识 |
| `VoidEventChannel` / `GameEventChannel<T>` | 跨系统事件通道 | 资产引用替代字符串 key，可 Find References、策划可连线 |
| `RuntimeSet<T>`（Transform/GameObject） | 运行时集合 | 替代 `GameObject.Find`，成员自己登记 / 摘除 |
| `GameEventListener` | 通道 → UnityEvent 桥 | 让策划在 Inspector 里连"播个音效、弹个特效" |

**序列化安全红线**

- `ScriptableVariable`：`InitialValue` 序列化落盘；`Value` 标 `[NonSerialized]`，Play 模式读写不污染资产。
- `RuntimeSet`：`Items` 刻意不序列化，防止场景实例引用被写进 SO 造成悬空引用。

### 3.8 架构护栏（`ArchitectureGuardrail`，Editor-only）

| 规则 | 检测内容 | 级别 |
|---|---|---|
| 硬反模式（共 **8** 条） | `GameObject.Find` / `FindGameObjectWithTag` / `FindGameObjectsWithTag` / `FindObjectOfType` / `FindFirstObjectByType` / `FindAnyObjectByType` / `Resources.FindObjectsOfTypeAll` / 业务层 `DontDestroyOnLoad` | Error |
| 软提醒 | **由工程自行配置**（`ArchitectureGuardrailSettings` 资产） | Warning |

> **软规则已外置**：框架不再硬编码任何业务类名。若要恢复"提示不要新增某类常量"式的提醒，
> 在 `Assets/Resources/` 创建一份 `ArchitectureGuardrailSettings` 资产
> （Create → `LFramework/Architecture Guardrail Settings`），在 `warningPatterns` 里填正则即可。
> 未创建该资产时软提醒为空，硬规则照常生效。

**触发方式**
1. 保存 `.cs` 时自动扫描被改动的文件（`AssetPostprocessor`）
2. 菜单 `Tools/LFramework/架构校验/全量扫描业务层`（结果写工程根 `Artifacts/ArchitectureGuardrail/report.json`，供 CI 消费）
3. 菜单 `Tools/LFramework/架构校验/构建时拦截反模式`（可选开关，默认关；开关按工程持久化在 EditorPrefs，跨编译/重启保留）

**作用域**：根目录为 `Application.dataPath + "/Scripts"`；排除目录 = 内置 `ExcludeDirs`（`/Core/` `/ThirdParty/` `/Editor/` `/Tests/` `/TestsPlayMode/` `/Plugins/` `/StreamingAssets/`）+ `ArchitectureGuardrailSettings.extraExcludeDirs`。
**豁免**：在触发行末加 `// ARCH_EXEMPT`。

## 5. 模块使用方式

### 5.1 模块系统（IModule）

**自定义模块**

```csharp
using Cysharp.Threading.Tasks;

namespace LFramework
{
    // MonoBehaviour 模块：会被 AddComponent 到 ModuleManager 所在物体
    public class MyService : UnitySingleton<MyService>, IModule
    {
        protected override void Awake()
        {
            base.Awake();
            if (_isDuplicate) return;
            // 自身初始化（MonoBehaviour 惯用）
        }

        public string DisplayName => GetType().Name;
        public async UniTask InitializeAsync() { await UniTask.Yield(); }  // 异步准备
        public void Dispose() { }                                        // 逆序清理

    // 纯 C# 模块：ModuleManager 通过静态 Instance 懒创建
    public class MyPureService : SingletonBase<MyPureService>, IModule
    {
        protected override void Init() { }
        public string DisplayName => GetType().Name;
        public UniTask InitializeAsync() => UniTask.CompletedTask;
        public void Dispose() { }

    // 需要逐帧：额外实现 ITickable。
    // ModuleManager 只对实现了 ITickable 的模块派发 Tick ——
    // 纯初始化型模块不实现它，就不会被每帧调用（不再被迫写空 Tick）。
    public class MyTickingService : SingletonBase<MyTickingService>, IModule, ITickable

        public string DisplayName => GetType().Name;
        public UniTask InitializeAsync() => UniTask.CompletedTask;
```

**把它加入清单**

1. 菜单 `LFramework/Create Module Manifest Asset` —— 会**自动扫描当前工程所有 `IModule` 实现**并生成清单（无需手写类型名），写入 `Assets/Resources/ModuleManifest.asset`
2. 生成后可在 Inspector 微调每行：

| 字段 | 填写内容 |
|---|---|
| `displayName` | 任意可读名（仅 Inspector 显示） |
| `typeName` | **完整类型名**，如 `LFramework.MyService`（菜单扫描时已自动填好） |
| `enabled` | 勾选 |
| `dependsOn` | 依赖模块的 `typeName` 数组，如 `["LFramework.ResourcesManager"]`（**依赖关系不会被自动推断，需手工补**） |

3. 排序由拓扑排序自动完成（手拖顺序仅决定无依赖模块之间的相对次序）。
4. 确认启动入口脚本上的模块清单字段指向该资产。

> **常见错误**：`typeName` 写简名（如 `MyService`）→ 报 `无法解析类型`；`dependsOn` 写了清单外的类型 → 报 `不在清单中，忽略该依赖`；声明成环 → 报 `检测到循环依赖` 并回退原始顺序。

**面板生命周期（严格按此顺序）**

打开一个新面板：

```
Instantiate 预制体 → GetOrAddComponent<T> → UIPanelBase.Awake()（自动控件绑定）
  → OnUIAwake()
  → await UniTask.Yield()
  → OnUIStart()
  → SetAsLastSibling → InitPanelData(data) → OnUIEnable() → await OnShowAnimation()
  → State = Open，广播 "UIManager.PanelOpen/{类型名}"
```

关闭面板：

```
OnUIDisable() → 广播 "UIManager.PanelClose/{类型名}"
   ├─ 有 [UIKeepAlive] 或 forceKeep → 仅 SetActive(false)，实例保留
   └─ 否则 DestroyPanel → OnUIDisable() → OnUIDestroy()（Destroy(gameObject)）
        → 广播 "UIManager.PanelDestroy/{类型名}" → 面板句柄 Dispose（`UIManager._panelHandles[type]`）
```

**打开已存在的面板**：不会重新 Instantiate，直接 `SetAsLastSibling → InitPanelData(data) → OnUIEnable → OnShowAnimation`。

**写一个面板**

```csharp
using UnityEngine;
using UnityEngine.UI;
using Cysharp.Threading.Tasks;
using LFramework;
using LFramework.UI;

namespace LFramework.UI
{
    [UILayer(UIPanelLayer.PopUp)]   // 不标则默认 Normal
```

配套步骤：
1. 预制体放 `Assets/Resources/Prefabs/UI/UIPanel/MyPanel.prefab`（文件名 = 类名）
2. 需要自动绑定的节点名与字段名**完全一致**（字段 `btn_Close` → 节点名 `btn_Close`）
3. 需要强类型数据时改用 `UIPanelBase<TData>`（重写 `InitPanelData(TData)`，数据为 null 或类型不匹配时安全退化为 `default`）

**控件自动绑定（`UIComponentBinding`）**

| 项 | 规则 |
|---|---|
| 前缀白名单 | `btn` `img` `obj` `text` `input` `slider` `scroll` `ui` |
| 命名格式 | `前缀_任意名`，下划线前一段命中白名单即生效 |
| 支持字段类型 | `GameObject` 或任意 `Component` 派生类型 |
| 查找方式 | 先 `transform.Find(字段名)`，未命中则全层级按节点名递归查找 |
| 触发时机 | `UIPanelBase.Awake()` 中自动执行一次 |

> 若子类重写了 `Awake()`，**必须调用 `base.Awake()`**，否则绑定不会触发。
> 找不到节点或组件会在 Console 输出 Warning（不抛异常）。

**层级（`UIPanelLayer`）**：`Normal` / `TopBar` / `PopUp`，默认对应 UIRoot 下同名子节点。

**路径与层级可配（`UISettings`）**：框架内置默认值开箱可用；换工程若目录结构或层级节点名不同，在 `Assets/Resources/` 放一份 `UISettings` 资产（Create → `LFramework/UI Settings`）改字段即可，**不必改框架代码**。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `rootPrefabPath` | `Prefabs/UI/UIRoot` | UI 根预制体路径（Resources 下） |
| `panelPrefabDir` | `Prefabs/UI/UIPanel` | 面板预制体目录 |
| `layerNodeNames` | 空（回退枚举名） | 各层级在 UIRoot 下的子节点名，顺序同枚举 |
**数据绑定（`BindableProperty<T>`）**

Model 的字段包一层，赋值即通知；面板订阅后在销毁时自动退订。

```csharp
// Model 侧
public readonly BindableProperty<int> Count = new BindableProperty<int>(0);
Count.Value = 3;                     // 值真的变化时才触发；同值赋值不触发
Count.ForceNotify();                 // 需要强制刷一次时

// 面板侧
protected override void OnUIStart()
{
    Bind(model.Count, v => text_count.text = v.ToString(), invokeImmediately: true);
}
```

- `Bind<T>(property, handler, invokeImmediately)` 建立的订阅会被登记，在 `OnUIDestroy()` 时**自动退订**，不必手写 `-=`。
- 保活面板（`[UIKeepAlive]`）隐藏时不销毁，订阅保留，重新显示时数据仍是最新的。
- 手动退订 `Unbind<T>(property, handler)`；一次性清空 `UnbindAll()`（public）。
- `Bind` / `Unbind` 是 `protected`，只能在面板子类内调用。

**UI 生命周期事件 key（`UIEventKeys`）**

框架广播的面板事件 key 已集中到 `UIEventKeys`，不要再自己拼字符串：

```csharp
EventCenter.AddListener(UIEventKeys.PanelOpen(nameof(MyPanel)), OnMainOpen);
EventCenter.AddListener(UIEventKeys.PanelClose(nameof(MyPanel)), OnMainClose);
EventCenter.AddListener(UIEventKeys.PanelDestroy(nameof(MyPanel)), OnMainDestroy);
```

对应 `UIManager` 在「显示完成 / 关闭 / 销毁」时广播的三个事件（内部前缀为 `UIManager.`）。

**面板状态与查询**

- `UIPanelBase.State`：`Opening` → `Open` → `Closing` → `Destroyed`。
- `UIManager.PanelDic`：`IReadOnlyDictionary<Type, UIPanelBase>`，可查当前已注册面板。
- `UIManager.Close<T>()` 默认**销毁**；标 `[UIKeepAlive]` 的只隐藏保活。

### 5.9 事件系统（EventCenter）

```csharp
// 订阅 / 退订（泛型参数类型必须与派发时完全一致）
EventCenter.AddEventListener("MyEvent", OnMyEvent);
EventCenter.AddEventListener<int>("ScoreChanged", OnScore);
EventCenter.RemoveListener("MyEvent", OnMyEvent);

// 令牌式订阅（推荐，Dispose 即退订）
using (EventCenter.Subscribe<int>("ScoreChanged", OnScore)) { }
IDisposable token = EventCenter.Subscribe("MyEvent", () => { });

// 派发（最多 5 个参数）
EventCenter.TriggerEvent("MyEvent");
EventCenter.TriggerEvent<int>("ScoreChanged", 10);
EventCenter.TriggerEvent<string, int, float, bool, int>("Complex", a, b, c, d, e);

// 运维 / 诊断
EventCenter.RemoveListener("MyEvent");        // 移除该 key 全部监听
EventCenter.ClearAllListeners();
EventCenter.GetListenerCount("MyEvent");
EventCenter.GetAllEventNames();
EventCenter.DebugPrintEventSystem();
```

**注意事项**

- 按 **字符串 key + 委托类型**双重索引。订阅 `Action<int>` 就必须用 `TriggerEvent<int>` 派发；泛型个数不一致会**静默不触发**。
- 重复添加同一委托会打 Warning 并拒绝。
- 无监听者时派发直接返回，不报错。
- 关闭 Domain Reload 时静态状态会跨 Play 残留，已在 `SubsystemRegistration` 阶段自动清空（泛型类经非泛型 `RuntimeSessionReset` 注册重置——引擎不会为开放泛型类型调用 `[RuntimeInitializeOnLoadMethod]`，2026-10-12 实测发现并修复）。

```csharp
LogManager.SetConsoleLogging(false);
LogManager.OnLogReceived += entry => { };   // 日志事件
var path = LogManager.Instance.GetCurrentLogPath();
LogManager.Instance.Flush(); / Close();
```

**配置**：`Assets/Resources/LogSettings.asset`，通过菜单 `LFramework/日志设置` 打开窗口编辑并保存。

**能力**
- 分级过滤（`Debug` → `Fatal`）、Console / 文件双写、双缓冲或实时落盘
- 日志按天轮转 + 保留 `SaveDays` 天 + 单文件上限 `MaxFileSizeMB`
- **敏感信息自动脱敏**：IP / MAC / 手机号 / 邮箱 / 身份证 / Token / URL 参数 / 银行卡 / IPv6
- 未捕获异常与 Unity 异常自动入库（`EnableExceptionCatcher`）
- 低内存告警自动触发 `ResourcesManager.ReleaseUnused()`
- 远程上传（`LogUploader`，HTTP / WebDAV，指数退避，默认关闭）

**日志路径**：`{persistentDataPath}/Logs/log_yyyyMMdd.txt`。
菜单 `LFramework/文件夹管理/查看路径/打开PersistentDataPath目录` 可直接打开。
**启动期缓冲（Phase 5 / 5.4）**

`LogManager` 不再被日志调用懒创建。在模块初始化（`ModuleManager.InitializeAsync`）**完成之前**打出的日志不会丢：先进静态缓冲（容量 256），到 `LogManager.InitializeAsync` 时回放。

```csharp
// 框架启动前就能安全打日志，不必先判空单例、也不必挪到 Start 之后
LogManager.Info("开始初始化模块");
await moduleManager.InitializeAsync(manifest);   // 缓冲在这一步被回放
```

**刷盘时机**：由 `LogManager.Tick(float)`（`ITickable`）驱动，经 MonoManager → ModuleManager 统一派发。业务侧不要自己起协程刷盘。

### 5.17 状态机（FSM）

框架只提供机制，**不预设任何状态**：状态 ID 与转换条件类型由使用方指定（枚举 / int / string 皆可）。

```csharp
// 1. 自定义状态与转换
public enum MyState { Null = 0, Idle, Run }
public enum MyTransition { Null = 0, Run, Idle }

// 2. 派生状态
public class IdleState : FSMState<MyState, MyTransition>
{
    public IdleState() { stateID = MyState.Idle; }
    public override void DoUpdate() { /* 每帧调用 */ }
}

// 3. 组装与驱动
var fsm  = new FSMSystem<MyState, MyTransition>();
var idle = new IdleState();
idle.AddTransition(MyTransition.Run, MyState.Run);   // 条件 → 目标状态
var run  = new RunState();
run.AddTransition(MyTransition.Idle, MyState.Idle);
fsm.AddState(idle);
fsm.AddState(run);
fsm.Start(MyState.Idle);              // 不调用则 PerformTransition 报错

fsm.PerformTransition(MyTransition.Run);   // 切换
fsm.CurrentState.DoUpdate();               // 需自行在 Update 中驱动
fsm.DeleteState(run);
```

> `TStateId` / `TTransition` 的 **`default` 值**（枚举第 0 项，或引用类型的 null）被当作"空"，不能用于真实状态与转换
> —— 因此枚举请把 `Null` 放在第 0 位。

### 5.18 网络与协议

**UDPDevice（底层）**

```csharp
var device = new UDPDevice(8888);                  // 绑定端口，失败抛 SocketException
device.DataReceived += OnData;                     // 主线程触发，可安全访问 Unity API
device.Update();                                   // 必须在主线程每帧调用，用于派发队列
// 或注册到自动更新器（推荐）
UDPDeviceAutoUpdater.Instance.RegisterDevice(device);

string one = device.GetData();                     // 手动取一条
foreach (var s in device.GetDataEnumerable()) { }   // 迭代全部

device.SendUdp(8888, "192.168.1.10", "Cmd");        // 发到指定 IP
device.Dispose();  // 或 device.UDPClose()
```

**关键设计**：接收在后台线程，数据入 `ConcurrentQueue`；`Update()` 在主线程出队并触发 `DataReceived`。队列有 10000 条滚动窗口上限（无人消费时丢最旧），退出时 `Join(500)` 优雅收线程。

## 7. 编码与架构约定

| # | 约定 | 说明 |
|---|---|---|
| 1 | 命名空间统一 `LFramework` / `LFramework.*` | 禁止引入 `XY.Framework` 等历史命名空间 |
| 2 | `.cs` 文件使用 **UTF-8 with BOM** | 含中文注释时尤为重要；编辑中文文件优先整文件重写而非局部替换，避免乱码 |
| 3 | 异步统一用 UniTask | 新代码不要再用 `IEnumerator` 协程。`MonoManager.StartCoroutine` 是**为业务兼容保留**的代理，框架内部一律用 UniTask（见 §3.6） |
| 4 | 资源加载统一走 `ResourcesManager.Instance` | 禁止直接 `Resources.Load`；Addressables 后端只能用 `LoadAsync<T>()` |
| 5 | UI 面板只用 `UIManager.Open/OpenAsync/Close` | 常驻面板加 `[UIKeepAlive]` |
| 6 | 不再使用 `ServiceLocator` | 已从框架移除；换加载器用 `ResourcesManager.SetLoader(...)` |
| 7 | 基类 Unity 魔法方法一律 `protected virtual` | 防止子类同名方法静默隐藏基类清理逻辑 |
| 8 | 派生 `UnitySingleton` 时 `base.Awake()` 后必须检 `_isDuplicate` | 否则重复实例会重复初始化 |
| 9 | `Time.timeScale` 唯一出口是 `GamePauseService` | 业务层禁止裸赋值 |
| 10 | 稳定业务事件走 SO `GameEventChannel` | 禁止再往字符串 key 的常量类加新常量 |
| 11 | `ScriptableVariable.InitialValue` 序列化 / `Value` 不序列化 | 防 Play 模式污染资产 |
| 12 | `RuntimeSet.Items` 绝不序列化 | 防跨场景悬空引用 |
| 13 | Core 管理器走 `.Instance`；业务模块跨依赖走 `GetModule<T>()` + `dependsOn` | 见 [3.5](#35-单例与访问约定) |
| 14 | 业务脚本不得放在 `Assets/Scripts/` 根下 | 会落入 `Assembly-CSharp`，无法引用 LFramework |
| 15 | 新增业务程序集时记得显式引用第三方依赖 | asmdef references 非传递性 |
